# Stop Prompting. Start Defining Outcomes.

Kilde: https://www.skool.com/cliefnotes/classroom/c7f102c7?md=30d2fc79158442cda43f86568a462c51

**Prompt-filosofi (Ari Evergreen).** Mindset-skifte fra tilfeldig prompting til utfalls-drevne briefer — tre prinsipper for å behandle AI som en kontraktør, ikke en spilleautomat. Kjernelinjen: **«A prompt is a wish. A brief is a contract.»** Hvis promptene dine leser som ønsker i stedet for kontrakter, får du tilfeldig output uansett modell — kvaliteten på output er begrenset av klarheten i input. Makere hun respekterer «kjører en workshop» i stedet for å trekke i spaken og håpe. Passer sammen med hennes fire-fase-byggemetode.

**Relevans for oss:** direkte grunnlag for `agent.md`-malen (Task + Output format = kontrakten), `/plan`-kommandoen, og `operations/DISPATCH.md` Mission Brief. Samme poeng som Foundation 1.3 og The Golden Rules «stage contracts». Kobler til [`four-phases-before-build.md`](four-phases-before-build.md).
